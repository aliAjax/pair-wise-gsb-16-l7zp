# hxwl-01 听力验配记录

门店听力师的助听器调试闭环工作台：登记左右耳增益、反馈等级与试听评分，确认冻结后再调试另建版本并保留旧值。

## 技术栈

React + Vite + TypeScript + CSS（localStorage 本地持久化，无后端）

## 本地运行

```bash
npm install
npm run dev      # 开发端口 5101
npm run build    # 类型检查 + 生产构建
npm run check    # 领域规则 36 项 + 页面闭环 27 项断言
```

## 调试闭环规则

- 每次调试登记：**耳别（左/右）+ 增益 dB + 反馈等级 + 评分**。
- **评分低于良好（< 3）或反馈超过二级（> 2）时，必须填写调整依据**；其余情况选填。
- 校验不通过不会产生记录，输入只保留为该「客户 + 耳别」的草稿。
- **同客户 + 同耳别只能有一条「等待确认」记录**；重复登记报冲突，冲突列出客户、耳别与双方增益。
- 确认后数值**冻结**，不可再改；在冻结基础上再调试会**新建递增版本**，必须填写调整原因，旧版本数值/依据经 `parentId` 完整保留。
- 草稿按「客户 + 耳别」独立槽位保存：切换客户/耳别不串台，刷新/重载后仍归属原位。
- 重载时做一致性巡检：客户、记录、草稿与版本链关系完整恢复；若发现重复等待确认记录，列冲突并支持「确认原记录」或「删除重复记录」。

## 分层结构（领域数据、校验规则与页面分离）

```
src/domain/            # 纯领域层，不依赖 React / DOM
  types.ts             # 数据结构：客户、记录、草稿、冲突
  rules.ts             # 校验规则（纯函数）：联动必填、区间、标签
  store.ts             # 状态机：登记/确认/版本/草稿/冲突/一致性巡检
  persistence.ts       # 快照持久化 + 重载恢复
  seed.ts              # 示例数据
src/state/
  useFittingStore.ts   # 适配器：React 与领域状态机之间，只做编排与通知
src/components/        # 表单、版本链、冲突面板
src/pages/FittingPage.tsx
scripts/
  check-domain.ts      # 领域规则/状态机断言（node 直跑）
  smoke.tsx            # jsdom + Testing Library 页面闭环冒烟
```

业务规则全部集中在 `src/domain/`，可脱离页面单独运行与测试；页面层不包含任何规则判定。
