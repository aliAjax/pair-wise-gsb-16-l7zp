# hxwl-01 听力验配记录

门店听力师的助听器调试闭环工作台：左右耳增益 / 反馈 / 评分登记、等待确认、确认冻结、复诊版本管理。

## 技术栈

React 19 + Vite + TypeScript + CSS；测试使用 Vitest（含 jsdom 端到端）。

## 本地运行

```bash
npm install
npm run dev      # 开发：http://localhost:5101
npm test         # 领域规则 + 持久化 + 页面端到端，共 21 个用例
npm run build    # tsc 类型检查 + 生产构建
```

开发端口：5101

## 调试闭环规则

1. 每次调试按「客户 + 耳别」登记：增益（dB，-10~60）、反馈等级（0~3）、听声评分（1~5）。
2. 评分低于良好（<3）或反馈超过二级（>2）时，**必须写调整依据**才能登记；否则只能保存草稿。
3. 同一客户同一耳别同时**只能有一条等待确认记录**；存在待确认记录时新调试被冲突拦截。
4. 确认后增益 / 反馈 / 评分**冻结**，任何入口都不能改确认版数值。
5. 冻结后再次调试**另建下一版本**：必须填写调试原因，并自动保留上一确认版旧值（增益/反馈/评分）。
6. 等待确认记录可撤回，数值退回该客户该耳草稿。
7. 冲突队列固定列出**客户、耳别、增益**（阻塞值与本次尝试值）。
8. 草稿按 `客户::耳` 物理隔离：切换客户/耳别未保存草稿只随原归属落库，绝不串台。
9. 状态持久化到 localStorage；重载时做结构校验与一致性自检（草稿归属、唯一待确认、版本连续、旧值一致），异常安全回退。

## 分层结构（领域数据、校验规则与页面分离）

```
src/
  domain/                # 纯 TypeScript，不依赖 React
    types.ts             # 领域模型：客户/记录/版本/草稿/冲突
    constants.ts         # 等级标签与判定门槛（良好=3、二级=2）
    validation.ts        # 纯校验：增益解析、依据/原因必填、登记条件
    store.ts             # 纯函数状态机：登记/确认/撤回/版本链/冲突/一致性自检
    persistence.ts       # localStorage 序列化、反序列化校验与安全回退
    *.test.ts            # 领域规则与持久化测试
  hooks/
    useFittingStore.ts   # React 适配：仅负责状态挂载、草稿隔离与事件转发
  components/            # 页面组件，只消费领域 API，不含业务规则
    FittingForm.tsx
    PendingPanel.tsx
    VersionTimeline.tsx
    ConflictPanel.tsx
    app.e2e.test.tsx     # 页面端到端：拦截→草稿→登记→确认→v2→重载
  App.tsx                # 布局与客户/耳别切换
```
